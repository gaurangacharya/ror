--------------------------------------------------------------------------------
AUTOMATED DEPLOY (recommended)
--------------------------------------------------------------------------------

sudo bash deploy-staging.sh
  → Normal deploy: pull code, fix permissions, migrate DB, restart web+worker,
    show health check. Use this for most code changes (Ruby, views, controllers).

sudo bash deploy-staging.sh --full
  → Full deploy: everything above PLUS rebuild Docker images, bundle install,
    and asset precompile. Use when Gemfile, Dockerfile.development, or
    package.json / client dependencies changed.

--------------------------------------------------------------------------------
WHAT deploy-staging.sh RUNS (step by step)
--------------------------------------------------------------------------------

git pull origin staging
  → Download latest code from GitHub into /opt/source/staging-ownoutdoorsc

chown -R 1000:1000 /opt/source/staging-ownoutdoorsc
  → Fix file ownership so the app user inside Docker can read/write files
    (needed after git pull creates root-owned files)

docker compose up --build -d
  → Rebuild Docker images and start all containers in background (--full only)

docker compose run --rm web bundle install
  → Install Ruby gems after Gemfile changes (--full only)

docker compose exec web bash -c 'cd client && npm ci && cd .. && bundle exec rake assets:precompile'
  → Install Node packages and compile JS/CSS/images for production (--full only)

docker compose run --rm web bundle exec rails db:migrate
  → Run any new database migrations from db/migrate/

docker compose restart web worker
  → Restart the web server (Passenger) and background worker (Sidekiq + search)

docker compose ps
  → Show status of all containers (web, worker, mysql, redis, etc.)

curl -sI https://jitsi.agiletechnologies.in/_health
  → Quick check that the app is responding (should return HTTP 200)

PART 4 — WHEN TO USE EXTRA COMMANDS
================================================================================

sudo docker compose up --build -d
  → Rebuild and start ALL services. Use when Dockerfile.development or
    docker-compose.yml changed.

sudo docker compose run --rm web bundle install
  → Install gems after Gemfile / Gemfile.lock changed (without full rebuild).

sudo docker compose exec web bash -c 'cd client && npm ci && cd .. && bundle exec rake assets:precompile'
  → Recompile assets after JS, CSS, or image changes. Fixes homepage 500 errors
    like "asset not present in the asset pipeline".

sudo docker compose restart web
  → Restart only the web container (faster than full restart).

sudo docker compose restart worker
  → Restart only the Sidekiq/search worker.

sudo docker compose exec worker bundle exec rake ts:rebuild
  → Rebuild Sphinx/Manticore search index after listing/search data changes.

sudo docker compose up -d
  → Start all containers if they are stopped (no rebuild).

sudo docker compose down
  → Stop and remove all containers (data volumes are kept).

PART 5 — LOGS & DEBUGGING
================================================================================

sudo docker compose ps
  → List all containers and whether they are Up or Exited

sudo docker compose ps -a
  → List all containers including stopped ones

sudo docker compose logs web --tail 50
  → Show last 50 lines of web server logs

sudo docker compose logs web -f
  → Follow web logs live (Ctrl+C to stop)

sudo docker compose logs worker --tail 50
  → Show last 50 lines of worker (Sidekiq + search) logs

sudo docker compose logs worker -f
  → Follow worker logs live

sudo docker compose logs mysql --tail 30
  → Show MySQL container logs

sudo docker compose run --rm web bundle exec rails c
  → Open Rails console for debugging

sudo docker compose exec web bash
  → Open a shell inside the running web container

curl -sI https://jitsi.agiletechnologies.in/_health
  → Health endpoint check (expect HTTP 200)

curl -sL -o /dev/null -w "%{http_code}\n" https://jitsi.agiletechnologies.in/
  → Homepage HTTP status (expect 200)
